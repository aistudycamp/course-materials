01

Setup

Setup gives Claude a place to work, gives the app a database, and gives you a way to see what is happening.

VS Code

VS Code is an IDE, an integrated development environment. It gives you one window for the project files, the terminal, and the code Claude changes. You do not need to learn every feature. You need to open the right folder and keep the terminal beside the files.

Open the folder

Choose File, Open Folder, then select your AI Study Camp folder from Week 1.

Open the terminal

Choose View, Terminal. It opens at the folder you selected.

Start Claude Code

Click inside the VS Code terminal, then type:

claude

Press Return. Claude starts inside the folder you opened. This is different from the desktop app. The desktop app is useful for chat and general work. VS Code plus the terminal is where Claude can see and change the whole codebase.

Supabase

Supabase is the hosted service that gives your app a database and user accounts. The database stores the tasks. Authentication identifies the person using the app. You create one course project and reuse it across builds.

  1. Create a free account at supabase.com.
  2. Create a project named ai-study-camp.
  3. Save the database password in your password manager. Do not put it in the project.
  4. Open the Supabase Setup guide and follow the Claude prompt.
  5. Confirm that Claude created supabase.md in your AI Study Camp folder and connected the Supabase MCP.
What is supabase.md?
It is a small Markdown file in your local course folder. It names the Supabase project and stores the safe connection details Claude needs. It is not Supabase itself. It is a note that helps Claude use the right project.

Do this before Plan. The Foundation tab assumes the Supabase project and MCP are ready.

02

Plan

Claude can write code at any time. The plan gives it a clear product to build instead of a pile of disconnected requests.

PRD

PRD means Product Requirements Document. It describes the user, the problem, the main flow, the first features, and the limits of the first version. It gives Claude a stable brief to work from.

Define the user

Who is using this? What are they trying to do?

Define the problem

What is frustrating or slow today?

Define the flow

What happens from opening the app to getting value?

Define version one

What must exist now, and what can wait?

Plan mode

  • Use Plan mode before Claude writes code.
  • Make the plan large enough to cover the user flow, pages, data, and risks.
  • Ask Claude to show you the plan before it edits files.
  • Ask Claude to grill you. It should ask questions until the product is clear.
  • Cut the first version down to one main flow and three core features.
Tell Claude: I want to build a small to-do app. Stay in Plan mode. Ask me one question at a time about the user, the problem, the main flow, the visual direction, the data we need to save, and what should wait. Challenge weak or unclear parts of my idea. Then write a PRD and a build plan. Do not write code until I approve the plan.

Use the PRD template if you want a blank starting point. You can also answer the questions directly in Claude.

03

Foundation

Foundation is where the plan becomes a real project. Claude creates the app structure, connects Supabase, and prepares the local version you can open in a browser.

Before you start:
You should already have VS Code open, Claude Code running in the project folder, supabase.md created, and the Supabase MCP connected.

What Claude is building

Frontend

The screens and controls people see and use in the browser.

Backend

The server-side code that handles requests, rules, and connections.

Database

The place where tasks, accounts, and other app data stay after a refresh.

Connection

The code that lets the frontend ask the backend to read and change database data.

The first build prompt

Tell Claude: Read the PRD and the approved build plan. Create the app foundation with Next.js. Use my AISC Supabase project from supabase.md and the Supabase MCP. Set up the frontend, the database connection, and the first page. Before making changes, explain what you will create and ask me before anything destructive.

Environment values

The app needs connection values to talk to Supabase. Local values go in .env.local. Vercel gets its own copy later. These values must stay out of GitHub. Ask Claude to explain which values are safe to expose and which are not.

04

Build

Build one slice at a time. Each slice should end with a browser check, not a wall of new code.

Core flow

Add, edit, complete, and delete a task. Refresh and confirm the data is still there.

Design

Choose the layout, colors, type, and details. Ask Claude for options, then make the call.

Accounts

Add sign up, sign in, and sign out after the basic task flow works.

Testing

Ask Claude to test the flow, inspect errors, and explain anything unclear.

The loop

AskOne change
RunLocal app
LookBrowser
CheckExpected result
SaveCommit
Keep saying: Make one change. Run the app. Show me how I can check it in the browser. If it does not work, explain the cause before fixing it.

Do not wait until the end to open the browser. The browser is where you see the frontend. Supabase is where you can inspect the saved data.

05

Publish

Publishing moves the app from your computer to a public URL.

Git and GitHub

Git saves versions of your code. GitHub stores a copy of that code online. You commit locally, push to GitHub, and give Vercel a repository to publish.

LocalYour computer
CommitSave a version
PushSend to GitHub
VercelBuild online
LivePublic URL

Vercel

Vercel is the host for the frontend and server code. It connects to GitHub, builds the app, and gives you a URL. The live app also needs the Supabase environment values in Vercel's settings.

  1. Confirm the app works locally.
  2. Ask Claude to commit and push the current version to GitHub.
  3. Connect the GitHub repository to Vercel.
  4. Add the Supabase environment values in Vercel.
  5. Open the live URL and test sign in, task changes, refresh, and sign out.
Tell Claude: Check the local app one last time. Review the files for exposed secrets. Commit and push the working version to GitHub. Then tell me exactly what I need to add in Vercel before I deploy.

INFORMATION

Core concepts

These are the words you will hear during the build.

Frontend

The part of the app people see and click in the browser. Pages, buttons, forms, cards, and visual design.

Backend

The code that runs behind the screen. It handles requests, rules, authentication, and connections to other services.

Database

A structured place to store information. Your to-do tasks need a database because they should still exist after you close or refresh the browser.

Supabase

A hosted Postgres database with authentication, a dashboard, and tools that Claude can use through the MCP.

Vercel

A hosting service that builds and serves your app at a public URL. It reads the code from GitHub.

VS Code

An IDE. It combines the project files, code editor, terminal, and extensions in one workspace.

Claude Code

A coding agent that reads the folder, edits files, runs commands, checks the result, and reports what it did.

MCP

A connection that lets Claude use an external system. The Supabase MCP lets Claude work with your database without making you write SQL.

GitHub

An online home for the code and its version history. It is also the source Vercel watches for new deployments.
