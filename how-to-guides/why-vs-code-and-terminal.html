Six Moments in Your Build

1. Your app won't start

  • npm run dev prints a red error.
  • It shows in the terminal, right under Claude.
  • Copy it, paste it to Claude, ask for a fix.

2. One word is wrong

  • Your button says "Add Taks".
  • Click the file in the VS Code sidebar, fix it, save.
  • Five seconds. No prompt, no waiting.

3. What did Claude change?

  • Open the Source Control panel in VS Code.
  • Every changed file is listed.
  • Click one to see before and after.

4. A guide says "run this"

  • Supabase, Vercel, and GitHub docs assume a terminal.
  • So does almost every tutorial and forum answer.
  • You know where it goes, or you hand it to Claude.

5. claude stops working

  • "command not found" after an install or update.
  • The fix is a terminal command.
  • You can read the error, then search it or share it.

6. You try another agent

  • Codex and Gemini CLI run in the same terminal.
  • Same folder, same files, same habits.
  • The Claude desktop app runs only Claude.

Can I Just Use the Desktop App?

Yes. We teach the VS Code terminal so you learn both.

The desktop app is a good pick when you want to:

  • Review changes in a visual, side-by-side view.
  • Run several Claude sessions at once.
  • Do quick work that doesn't need an editor open.

Switch any time. Your files stay the same in every window.

1

Open Your Folder

In VS Code, choose File > Open Folder and pick your app folder from your Week 1 home base.

2

Open the Terminal

Choose Terminal > New Terminal, or press Ctrl + `. It opens inside that folder.

3

Start Claude
