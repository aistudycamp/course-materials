The stack, in plain language

The pieces Claude uses to turn an idea into a working app.

The five things to keep straight

ThingWhat it doesWhere you see it
VS CodeThe workspace where you see files and open a terminal.Your computer
Claude CodeThe coding agent that reads the project, edits files, runs checks, and explains its work.VS Code terminal
Next.jsThe framework that gives the app its pages, components, and server routes.Your project files
SupabaseThe hosted database and account system that stores the app's data.Supabase dashboard and app
VercelThe host that makes the app available at a public web address.Your live URL
GitHubThe remote copy of your code and its history.github.com

Local, hosted, and live

Localhost is the copy running on your computer while you build. Supabase is where the data lives. Vercel is where other people can open the published app.

Helpful test: if a change works on localhost but not on the live URL, the code is probably fine and the deployment settings need checking.

What to ask Claude

You do not need to memorize the stack. Ask Claude to explain which piece it is changing:

claude
Before you make this change, tell me which part of the stack it touches and how I can check it.
