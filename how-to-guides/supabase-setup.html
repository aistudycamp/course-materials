How-To Guide

Supabase Setup

A free account, one project, and one prompt that connects Claude Code to it. You do this once.

Why One Project

Every build in the course stores its data in the same Supabase project, named ai-study-camp. Set it up once and Claude handles the database in every build after that. How it works inside your apps is the next guide, Build with Supabase.

1

Create an Account

Go to supabase.com and sign up for a free account. Signing in with GitHub is the fastest path, since you already have one from Week 1.

2

Create a Project

Click New project and name it ai-study-camp, exactly that. Supabase asks for a database password: generate one and save it in your password manager. You won't need it day to day.

Tip

The name matters. The prompt in step 3 and every later build refer to the project as ai-study-camp.

3

Paste the Setup Prompt

Open Claude Code and paste this:

claude
I just created a Supabase account with a project called ai-study-camp for my course. Set it up so all my course projects can use it: 1. Find my AI Study Camp folder in my home base (create one under learning if it doesn't exist) and create a file in it called supabase.md 2. Walk me through finding my Project URL and publishable key (called anon public key in older dashboards) in the Supabase dashboard, then save both in supabase.md, labeled, along with the project name and a line on what this project is for. Never save the service role key or my database password anywhere 3. Connect the official Supabase MCP using its browser sign-in flow. Approve access only for this course project, confirm that the connection is active, and keep any MCP credentials out of the project files. 4. Create or update the CLAUDE.md in my AI Study Camp folder with: builds here use my ai-study-camp Supabase project (connection info in supabase.md), Next.js for the frontend, Supabase for the database and login, Vercel for deploys, each build gets its own tables, and schema changes go through the Supabase MCP 5. When you're done, show me the supabase.md file and confirm the MCP is connected

Claude walks you through the dashboard clicks, saves your connection info, and connects the Supabase MCP server. When it finishes, it shows you supabase.md and confirms the MCP is connected. That's the whole setup.

Troubleshooting

MCP shows as not connected

If browser authorization is not active, ask Claude to reconnect the official Supabase MCP and complete the sign-in step again.

"Invalid API key"

You copied the service role key by mistake, or the string got cut off. Re-copy the publishable key (called anon public key in older dashboards) from the dashboard, the full string, and have Claude update supabase.md.

Project shows as paused

The free tier pauses a project after about 7 days without activity. Open the dashboard and click Restore. It comes back in a minute or two with all your data.

Claude asks for the service role key

Say no. Claude works through the MCP and never needs that key. Tell it to use the Supabase MCP instead.
