How-To Guide

Supabase Setup

A free account, one project, and one prompt that connects Claude Code to it. You do this once.

Why One Project

Every build in the course stores its data in the same Supabase project, named ai-study-camp. Set it up once and Claude handles the database in every build after that. How it works inside your apps is the next guide, Build with Supabase.

1

Create an Account

Go to supabase.com and sign up for a free account. Signing in with GitHub is the fastest path, since you already have one from Week 1.

2

Create a Project

Click New project and name it ai-study-camp, exactly that. Supabase asks for a database password: generate one and save it in your password manager. You won't need it day to day.

Tip

The name matters. The prompt in step 3 and every later build refer to the project as ai-study-camp.

3

Paste the Setup Prompt

Open Claude Code and paste this:

claude
I just created a Supabase account with a project called ai-study-camp for my course. Set it up so all my course projects can use it: 1. Find my AI Study Camp folder in my home base (create one under learning if it doesn't exist) and create a file in it called supabase.md 2. Walk me through finding my Project URL and anon public key in the Supabase dashboard, then save both in supabase.md, labeled, along with the project name and a line on what this project is for. Never save the service role key or my database password anywhere 3. Walk me through creating a personal access token in the Supabase dashboard, then install the official Supabase MCP server with it, user-scoped so it works in every project. Keep the token in the MCP config only. In future builds you'll use this MCP to create tables and columns for me, so I never write SQL myself 4. Create or update the CLAUDE.md in my AI Study Camp folder with: builds here use my ai-study-camp Supabase project (connection info in supabase.md), Next.js for the frontend, Supabase for the database and login, Vercel for deploys, each build gets its own tables, and schema changes go through the Supabase MCP 5. When you're done, show me the supabase.md file and confirm the MCP is connected

Claude walks you through the dashboard clicks, saves your connection info, and installs the Supabase MCP server. When it finishes, it shows you supabase.md and confirms the MCP is connected. That's the whole setup.

Troubleshooting

MCP shows as not connected

Tokens expire or get revoked. Create a fresh personal access token in the Supabase dashboard and ask Claude to reinstall the Supabase MCP server with it.

"Invalid API key"

You copied the service role key by mistake, or the string got cut off. Re-copy the anon public key from the dashboard, the full string, and have Claude update supabase.md.

Project shows as paused

The free tier pauses a project after about 7 days without activity. Open the dashboard and click Restore. It comes back in a minute or two with all your data.

Claude asks for the service role key

Say no. Claude works through the MCP and never needs that key. Tell it to use the Supabase MCP instead.
