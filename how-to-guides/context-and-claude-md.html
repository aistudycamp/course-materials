How-To Guide

Context and CLAUDE.md

Session habits, and how CLAUDE.md works at the global and project level.

Why Context Matters

Claude keeps a running memory of everything said in a session: every file it read, every change it made, every decision you discussed. Mix two unrelated projects into one chat, and Claude carries both at once. It can bleed into your work in subtle ways, wrong file, wrong assumption, wrong project.

1

Keep My Projects in Separate Chats

Claude keeps the conversation, files, decisions, and assumptions from a session in context. If you mix unrelated projects into one chat, those contexts can bleed together.

The rule: one project, one chat. Use a separate chat for your website, your job search, and a client's app. Start a new chat when you switch projects, even if you stay in the same folder.

Tip

Separate chats are the clean boundary between projects. The next point covers what to do when you want to keep working on the same subject.

2

Use Compact and Clear

Use these commands when you are continuing the same subject but need to manage the chat's context.

Clear

/clear

Start over in the same chat on the same subject. It gives you a clean slate without opening a new project chat.

Compact

/compact

Compress the conversation while keeping the important context. Use it when the context window reaches roughly 40–50%.

Remember: use a new chat between projects. Use /clear or /compact when you are continuing the same subject.

3

What Is CLAUDE.md?

It's a file Claude reads at the start of every session in a folder. Think of it as a briefing document: what this project is, how it's structured, how you want Claude to behave in it.

Say this in a new chat, in the project's folder:

claude
Look at this project and create a CLAUDE.md for me based on what you see.

Claude reads your files and drafts a starting point. Edit from there, it's faster than writing one cold.

4

Global and Project CLAUDE.md

CLAUDE.md works at two levels. One global file that loads everywhere, and one file per project that loads only there.

~/.claude/CLAUDE.md Global. Who you are, how you communicate, the people you work with. Loads in every project.
project-a/CLAUDE.md This project only
project-b/CLAUDE.md This project only
project-c/CLAUDE.md This project only

Put things you'd repeat in every project in the global file. Put things specific to one project in that project's own file. Claude loads both, global first.

5

Add the Three Core Sections

A good CLAUDE.md has three things: Identity, Rules, and Context.

Identity, what is this project, one or two sentences.

CLAUDE.md
# My Recipe App A web app that helps people find recipes based on ingredients they have at home. Built with React and Instant DB.

Rules, how should Claude behave in this project.

CLAUDE.md
## Rules - Keep the UI simple and mobile-friendly - Use Tailwind CSS for all styling - Never delete existing recipes from the database without asking first

Context, what does Claude need to know about the structure.

CLAUDE.md
## Key Files - `src/App.tsx` -- Main app component - `src/db.ts` -- Database connection and queries - `instant.schema.ts` -- Database schema
6

Point to Other Files Instead of One Giant File

This is context management done through CLAUDE.md itself. Instead of one file that tries to hold everything, point to separate files by topic:

CLAUDE.md
## Context For how I communicate, see @docs/communication-style.md For the people I work with, see @docs/contacts.md For how the front end is built, see @docs/architecture.md

The @filename syntax tells Claude to load that file too, only when it's relevant. Your main CLAUDE.md stays short, a table of contents, and Claude loads the deep material on demand.

  • › Sub-folders can have their own CLAUDE.md too, and it loads automatically when Claude works in that folder.
  • › If a topic keeps growing, give it its own file and point to it. Don't let the main file grow instead.
7

Verify Claude Actually Read It

Don't assume it loaded. At the start of a session, ask:

claude
What does my CLAUDE.md say?

If Claude summarizes it correctly, it loaded. If it hesitates or gets it wrong, the file is in the wrong location, or has a syntax issue.

8

Keep It Short, Keep It Current

A good CLAUDE.md is short. If the main file runs past 40 to 50 lines, that's the signal to split it, not to keep adding.

Every time you correct Claude on the same thing twice, add it to CLAUDE.md. You can just say:

claude
Add a rule to CLAUDE.md: always use early returns instead of nested if statements

Bad: "This is a project. Please help me."

Good: "A personal budget tracker built with React. Use Tailwind for styling. The main data lives in src/data/transactions.ts. Never mock data, always use the real Instant DB."

Troubleshooting

Claude seems confused about which project we're working on

You're probably in a chat that's mixed two projects. Start a new chat for the current one.

Claude keeps referencing something from earlier that doesn't apply anymore

Context bleed. A new chat, or /clear, fixes it.

Session feels sluggish

Try /compact first if you want to stay in the same chat. A new chat works too.

Claude keeps forgetting my preferences

Check the file is at the project root, not a subfolder, and check whether it belongs in the global file instead.

Claude ignores a rule

Be more specific. "Write clean code" is vague. "Use early returns instead of nested if statements" is actionable.

File is getting too long

Split it. Move a topic to its own file and point to it with @filename.
