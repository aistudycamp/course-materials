How-To Guide

Build with Supabase

One project, one table set per build, and Claude doing the database work through the MCP.

What Supabase Gives You

Your ai-study-camp project (set up in Supabase Setup) gives every app you build four things:

  • A real Postgres database that holds your app's data
  • Login, so your app can have user accounts
  • Realtime sync, so a change shows up in every open browser without a refresh
  • A hosted dashboard where you can see every row
1

Start in Your AI Study Camp Folder

Start Claude Code in your AI Study Camp folder and name the project in your first prompt. Claude reads supabase.md for the connection info.

claude
Build me a habit tracker. Use my ai-study-camp Supabase project for the database, connection info is in supabase.md.
2

Claude Creates the Tables

Claude creates this build's tables and columns through the Supabase MCP. You never write SQL. Later changes work the same way: describe what you want and Claude updates the table and the app in the same pass.

claude
Add a streak count to each habit and show it on the habit card.
3

Claude Wires the App

Inside the app, Claude installs the @supabase/supabase-js library and puts your Project URL and anon public key in .env.local. That's the whole connection. When you deploy to Vercel, the same two values go in the Vercel dashboard.

The Two Keys

Supabase gives your project two keys, and they are nothing alike. The anon public key ships inside every deployed app, so anyone can see it. That's fine, it only does what your access rules allow. The service role key bypasses every rule. Never share it, never save it. The course never uses it.

Rule

If anything asks for the service role key, say no. Claude does its database work through the MCP.

Checking Your Data

Open the Supabase dashboard and click Table Editor. Every table in your project is there, and clicking one shows the rows. When something in your app looks wrong, look here first: if the row exists, the bug is in the app, and if it doesn't, the save never happened.

One Table Set per Build

Every build gets its own tables in the same project, prefixed by week: week2_habits, week3_recipes. Nothing collides, old builds keep working, and the Table Editor stays readable. Claude follows this from the CLAUDE.md in your AI Study Camp folder.

Troubleshooting

Claude doesn't know which project to use

Say "use my ai-study-camp Supabase project, connection info is in supabase.md." If supabase.md doesn't exist, do the Supabase Setup guide first.

New rows don't show in the Table Editor

Refresh the dashboard and check you're looking at this build's tables, the ones with this week's prefix.

"Invalid API key" in the browser

The app got the wrong key or a cut-off one. Ask Claude to re-copy the anon public key from supabase.md into .env.local and restart the dev server.

The app worked last week and now nothing loads

The free tier pauses a project after about 7 days without activity. Open the dashboard and click Restore. All your data comes back with it.
