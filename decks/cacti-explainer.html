How Cacti Navigates

The Registry — Cacti's map of everything

When you mention a project, Cacti looks it up in a single routing file called knowledge/registry.md. That file maps plain-English names to folder paths.

What the registry looks like
ALIASES YOU SAY → FOLDER PATH
quote, bf, bitfreighter→nuvocargo/quote/ schedule, appts, scheduling→nuvocargo/schedule/ build, shipments, tenderbot→nuvocargo/build/ edi, sor, accept→nuvocargo/edi/ nuvops, lifecycle, facility→nuvocargo/nuvo-ops/ money, cash, finances, bills→personal/finances/ wedding, elena, rings, venue→personal/wedding/ la paz, move, baja, relocation→personal/la-paz/ aisc, ai study camp, cohort→aisc/internal/
Self-improving: When Cacti resolves a new alias not in the registry, it silently adds it. The map grows with every session.
Multiple aliases, one path: Saying "bitfreighter", "bf", or "quote" all land you in the same folder — Cacti resolves the intent, not the exact word.
What happens when you mention a project
1
You say something
"help me with the scheduling agent" or "what's blocking on build?"
2
Cacti looks up the registry
"schedule" → ~/cc/nuvocargo/schedule/
3
Goes to that folder & reads CLAUDE.md
The project's instructions, context, conventions — Claude now has full project context without you explaining anything.
4
Takes action or reports back
Reads TASKS.md, checks Slack, queries Linear, runs code, writes files — all in the right context.

The learnings loop

Correction or ✓

PostToolUse hook fires after every skill. Learnings are read before the next run and applied without any prompting from Ben.

Memory

Four memory layers

Each layer has a clear lifespan and loading contract.

1
Global rules — always-on behavior
~/.claude/CLAUDE.md + rules/*.md
Loads in every CC session everywhere. GitHub routing, communication style, augmentation rules. The standing operating contract.
Every session
2
Auto-memory — project & topic knowledge
~/cacti/memory/MEMORY.md + topic files
MEMORY.md (the index, <200 lines) auto-loads via system-reminder. Full topic files load on-demand — user_profile.md, project_*.md, feedback_*.md. 4 types: user, feedback, project, reference.
Index always, topics on-demand
3
Active context — daily continuity
~/cacti/HANDOVER.md
Read at every session start. Open threads (with status + last-touched dates), recent decisions, pending actions, session log. Updated at every session end — automatic, no permission needed.
Session start + end
4
Skill learnings — per-skill feedback loop
~/.claude/skills/*/learnings.md
Read before each skill run, written after corrections or confirmations. PostToolUse hook reminds Claude automatically. Skills improve across sessions without any manual maintenance.
On skill invocation
What NOT to save in memory: Code patterns, file paths, git history, debugging solutions, ephemeral task details. These live in the code or commit messages — not memory files.

Common failure: stale env (not expiry)

When personal MCP returns 401 — the token is almost never expired. CC captured the old PAT at spawn time. Fix: restart Claude Code. Always diff zshrc vs env var first before rotating a token.
# Check zshrc token vs running env
ZSHRC=$(grep "TIOBENITO=" ~/.zshrc | sed -E 's/.*=//')
curl -H "Authorization: token $ZSHRC" api.github.com/user -w "%{http_code}\n"
