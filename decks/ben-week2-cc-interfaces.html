The interfaces, the layers, and why we picked our setup.

It's all one model.

Claude — the brain behind all of this — is one model. What changes is the shell around it. A new interface doesn't mean a new AI. It means a different wrapper over the same thing.

Conversation

Claude.ai Chat

You type. Claude responds. Nothing changes on your computer. Single turn.

Delegation

Claude Cowork

You give Claude a goal. It works on your files and hands you a finished document.

Collaboration

Claude Code

Claude works inside your codebase — reads, edits, runs commands. Full access.

The spectrum: Chat → Cowork → Code = increasing autonomy, power, and technical depth. Same model. Completely different permission level.

The terminal — why you still need it.

The terminal is the foundation. Even as wrappers get better, you can't avoid this layer entirely — it's where you install things, run servers, and have the most raw control.

  • Installing Claude Code itself — npm install -g @anthropic-ai/claude-code
  • Running dev servers — npm, bun, python, whatever your stack needs
  • Git on the command line — commits, branches, pushes
  • Package managers — brew, npm, pip, cargo
  • Anything before the AI layer exists
You don't need to love the terminal. You just need to not fear it.

VS Code: a terminal with context.

VS Code isn't just an editor — it's a terminal wrapper with a file tree, source control, and a live editor all in one window. You get all the terminal power, plus you can see everything Claude is working on.

  • File tree — see every file Claude touches, live
  • Integrated terminal panel — same bash/zsh, embedded in the IDE
  • Git sidebar — stage, diff, commit without leaving VS Code
  • Editor open alongside — review changes in context

This is why "VS Code + terminal" became the default dev environment for vibe coding — it's the terminal, just more visible.

Claude Code in the terminal. Home base.

Type claude in the VS Code terminal and you're in. This is the setup we teach — and it gives you the most control.

  • Full Claude Code capabilities — memory, MCP servers, skills, hooks
  • CLAUDE.md project memory — Claude knows your codebase
  • File edits show up in VS Code — you see changes instantly
  • Git runs in the same terminal — no context switching
  • Portable config — what you learn here works everywhere
Everything Claude does is visible in the editor alongside you. That's the point.

The VS Code extension.

The Claude Code VS Code extension puts a chat-like sidebar inside VS Code. Same Claude Code underneath — different chrome. Great if you'd rather not look at a terminal.

  • Sidebar panel — interact with Claude without a terminal visible
  • Inline diffs — see proposed changes highlighted in the file, accept or reject line by line
  • @-mention files — reference specific files by name instead of describing them
  • Diagnostic sharing — linter and TypeScript errors automatically shared with Claude
  • Plan mode — Claude shows its plan as a markdown doc before touching anything

Also works in Cursor and Windsurf — same extension, different IDE.

Claude Desktop. April 2026.

The April 2026 redesign turned the Desktop app into a serious visual workstation. For the first time, it has a real terminal built in — meaning you might not need VS Code at all.

  • Built-in terminal new — opens in your project directory, runs tests and builds without leaving the app
  • File editor + viewer new — click a file path in chat to open and edit it in a pane
  • Visual diff viewer — review all changes graphically, leave inline comments
  • Parallel session sidebar — run multiple Claude sessions at once, each in its own git worktree
  • Drag-drop pane layout — arrange terminal, editor, diff, and chat into any grid
  • Side chat (⌘;) — quick question without breaking your main session's context

Cursor: different IDE, same model.

Cursor is an IDE built from the ground up for AI-assisted development — it forked VS Code and added AI-native features at every layer. If you end up preferring it, everything you learned still applies.

  • Claude Code extension works in Cursor — same extension from the VS Code Marketplace, same experience
  • Set Claude as Cursor's native AI model — Sonnet or Opus as the model powering Cursor's built-in features (⌘K, chat, composer)
  • Run Claude Code in Cursor's terminal — type claude, same CLI, same config
  • Different IDE, same CLAUDE.md — your project memory file follows you
Cursor = different shell, same Claude brain. Pick the IDE that feels right.

The honest answer

Why we teach it this way.

We had to pick one. VS Code + Claude Code in the terminal is the most widely used setup among working developers today. It's not the only answer — it's our answer.

What you learn transfers. CLAUDE.md, MCP servers, skills, and hooks work across every interface. The config is portable. The interface is a preference.

The terminal gives you the most control. You can do things in the terminal that no visual wrapper can do: pipelines, CI/CD, scripted agents. It's the floor, not the ceiling.

The layers are converging fast. The Desktop app is catching up quickly. In a year, you might never open a terminal. Learn the terminal layer now — it makes every layer above it easier to understand.
